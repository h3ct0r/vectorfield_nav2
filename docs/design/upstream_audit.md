# Upstream audit: adrianomcr/vectorfield_stack

This is the audit of the ROS 1 reference implementation of the vector-field method, written at M0. It answers four questions for implementers and users:

- what upstream does and where each feature lives in vectorfield_nav2;
- which upstream defects our design must not repeat, and which test proves it;
- how upstream parameters, messages and topics map to ours;
- what behaves differently after migrating.

"Plan §N" refers to the approved implementation plan (revision 6), whose design content is distilled into `docs/design/`. Symbols (v_r, k_f, λ, D_in, D′_in, σ, d) follow the plan's symbol table and `math_spec.md`.

## 5. Behavioural differences users will notice

1. **Open paths end with a controlled stop at the goal.** Upstream cut the speed from v_r to 0 when the nearest sample was the last one, wherever the robot was (U10). vectorfield_nav2 brakes over the last `terminal_braking_distance` (0.5 m) towards `min_approach_speed` and stops at the goal. Completion is decided by Nav2's goal checker (plugin) or the `settled` rule (follower). When the checker requires a goal yaw, ROTATE_TO_HEADING turns the robot in place at the end.
2. **No Python in curve definitions.** Expressions use muParser, with one string per axis, `s` (and `t`) as the variables and declared parameters (U01, §4.2). Invalid curves are rejected with INVALID_CURVE before the robot moves, not discovered mid-run.
3. **Curves are action goals.** `follow_curve` reports progress (distance to the curve, arc length, lap, phase) and ends with a result code. Cancel, preemption and `laps` replace re-publishing a path. A closed curve with `laps` = 0 runs until cancelled, as upstream did; with `laps` > 0 it stops after that many laps. A reversed open curve now stops at its first point.
4. **Commands are bounded and smooth.** Velocity, acceleration and, for Ackermann, curvature limits apply; upstream published the raw field. Starts, stops and recoveries from far off the path are slower but continuous.
5. **No unintended reversing.** Differential and skid-steer robots rotate in place when the field points more than 90° away from their heading (`rotate_to_field_angle`), and resume once within 45° (`rotate_to_field_release_angle`). Upstream feedback linearization would command a negative speed. Reversing requires `allow_reversing` or `drive_backward`.
6. **Paths are tracked segment by segment.** No densification or filtering is needed. Sparse plans no longer scallop, and corners keep their geometry: the follower can optionally fillet corners within `max_corner_deviation`.
7. **Re-localisation is automatic.** After an AMCL jump or a large pose step, the follower re-acquires the curve through its global search, and the plugin searches the freshly pruned plan window every cycle. At a self-intersection the follower stays on its current branch (hysteresis and detour test).
8. **Obstacles come from the costmap, and contouring is gated.** Every lethal cell of the local costmap counts, not one externally supplied point (U17, U24). By default the contour engages only when the path ahead is blocked (`obstacle_activation: path_blocked`); `always` restores the upstream rule. The side is chosen once per episode and kept, and a watchdog ends long detours. `obstacle_mode` defaults to `none`; the demos enable `contour`.
9. **The robot stops before collisions.** A rollout over `collision_check_horizon` caps the speed so the robot stops `stop_margin` short of a predicted collision. A blocked plugin raises NoValidControl, so Nav2 replans or recovers. The follower waits and returns BLOCKED after `blocked_timeout`.
10. **Missing data stops the robot.** Stale pose, odometry, costmap or frame input decelerates the robot and ends the goal (STALE_INPUT or TF_ERROR). Upstream kept the last command, or published nothing while the base kept moving (U33).
11. **The output is a body-frame twist on Nav2's command chain.** Skid-steer wheel arrays are gone. Omnidirectional commands are body-frame (v_x, v_y, ω); upstream's integrator published world-frame velocity. Commands pass through velocity_smoother and collision_monitor.
12. **Planar only.** z is ignored, so the 3D example curves become their planar projections. The 3D integrator and the quadrotor controller have no equivalent.
13. **Moving curves work.** With `frame_motion: FRAME_MOVING` (frame twist from Odometry or TF), the paper's feedforward Φ_T with η normalisation tracks translating and rotating curves; upstream had only static fields.
14. **Defaults differ.** `desired_speed` is 0.4 (upstream YAML 0.5), `convergence_gain` 2.0 (5.0) and `control_point_offset` 0.2 (0.1). Copying the upstream gains unchanged gives a validator warning (§4.1); re-tune with the tuning guide.
15. **RViz shows what the controller is doing.** Upstream drew only the path, the simulated robot, obstacles and the closest obstacle point. vectorfield_nav2 publishes `<ns>/markers`, toggleable per namespace:
    - `status`: a text label coloured by phase, with speed, D, σ and active flags such as BLOCKED and CONTOUR ±1;
    - `field`: the field decomposition arrows (convergence, circulation, feedforward and result);
    - `command`: the commanded velocity and its 1 s arc;
    - `heading`: the rotate target;
    - `prediction`: the predicted path and the first collision;
    - `goal`: the goal, the tolerance rings and the braking zone;
    - `contour`: the gate samples, the obstacle component, the λ / D_in / D′_in rings, the chosen side and the watchdog progress.

    It also publishes `field_grid`, `predicted_path`, `window` and `field_state`. The shipped `rviz/vectorfield.rviz` opens with every demo (plan §4.1).

## 7. Open items

The initial global search must resolve it to the start (direction +1) or the robot may settle at once. `math_spec.md` must state the tie rule; test U12 should be extended once it does.
